## What This Project Is

A set of Instruqt hands-on coding labs for teaching the Temporal SDK. Each lab
is a self-contained coding exercise where learners implement missing pieces of
a Temporal workflow in a browser-based VM with VS Code, terminals, and a live
Temporal server.

Current tracks:
- `temporal-java-hands-on` (live) — 4 exercises, Java SDK, order fulfillment scenario
- Python AI agents track (planned)
- Additional Java modules planned: Continue-As-New, encryption, claim check pattern

## Infrastructure

**VM image:** `instruqt/docker-28-3` (Ubuntu with Docker pre-installed)
**Docker image:** `ghcr.io/mmerrell/temporal-java-sandbox:latest` (public)
**Temporal server:** Runs as systemd service inside the VM (`temporal server start-dev --ui-port 8080 --ip 0.0.0.0`)
**VS Code:** `code-server` as systemd service on port 8443, with `vscjava.vscode-java-pack` installed
**Maven cache:** Pre-warmed for all 8 pom files during track setup

Each challenge has three tabs: VS Code (default), Terminal 1 - Worker, Terminal 2 - Starter, Temporal Web UI.
Exercise files land at `/workspace/exercise/src/main/java/fulfillment/`.

## The Three Sync Loops

| What changed | What to do |
|---|---|
| `exercises/` source code | `git push` → triggers image rebuild automatically |
| `docker/Dockerfile` | `git push` → triggers image rebuild automatically |
| `track/` scripts or `assignment.md` | `instruqt track push` from `track/`, then `git add/commit/push` |
| Instruqt generated IDs after first push | `instruqt track pull`, then `git add/commit/push` |

## assignment.md Rules

Instruqt is strict about this format. Key rules Claude must follow:

1. **Never use `---` inside assignment content** — use `***` for horizontal rules
2. **`slug`** must equal directory name minus the `NN-` prefix (e.g., dir `01-converting` → slug `converting`)
3. **`id` fields** on challenges and tabs are generated by Instruqt — don't add them manually for new content, don't change existing ones
4. **First tab** in the tabs list is the active tab on load
5. **`notes:`** is the pre-challenge splash screen (shown before learner clicks Start)
6. **Assignment content** is plain Markdown after the closing `---`
7. **`type: challenge`** for coding exercises (not `type: quiz`)

Example frontmatter structure:
```yaml
---
slug: converting
id: byvjpgcuvsa4
type: challenge
title: 'Exercise 1: Converting a Workflow'
teaser: One-line summary
notes:
- type: text
  contents: |-
    Markdown shown before Start button.
tabs:
- title: VS Code
  type: service
  hostname: workshop-host
  port: 8443
  path: ?folder=/workspace/exercise
- title: Terminal 1 - Worker
  type: terminal
  hostname: workshop-host
  workdir: /workspace/exercise
- title: Temporal Web UI
  type: service
  hostname: workshop-host
  port: 8080
  path: /
difficulty: basic
timelimit: 2400
enhanced_loading: null
---
```

## Check Script Pattern

All check scripts follow this pattern:

```bash
#!/bin/bash
EXERCISE_DIR="/workspace/exercise"
TARGET_FILE="$EXERCISE_DIR/src/main/java/fulfillment/SomeFile.java"

fail() { echo "FAIL: $1"; exit 1; }
pass() { echo "PASS: $1"; }

# Source grep checks
if grep -q "badPattern" "$TARGET_FILE"; then
  fail "Descriptive message shown to learner"
fi
pass "What was verified"

# Always end with compile check
cd "$EXERCISE_DIR"
if ! mvn compile -q 2>&1; then
  fail "Project does not compile. Fix compilation errors above and try again."
fi
pass "Project compiles successfully"
```

Checks are source grep + compile only — no end-to-end workflow execution.
Exit 0 = pass, non-zero = fail.

## Instruqt CLI Commands

```bash
cd track/
instruqt track validate          # Local validation (no network)
instruqt track push               # Push to Instruqt
instruqt track push --force       # Push overwriting remote (use when checksums diverge)
instruqt track pull               # Pull remote state
instruqt config get team          # Should return "temporal"
```

## Known Limitations

- **VS Code sidebar/file state** is stored in browser IndexedDB, not server-side.
  `settings.json` and `.code-workspace` files affect editor preferences but NOT
  which files are open or whether sidebars are visible on first load. Don't spend
  time trying to solve this server-side — it can't be done without a custom
  VS Code extension or Instruqt platform support.

- **Track startup time** is 5-10 minutes (setup script installs everything from scratch).
  This is an Instruqt platform constraint for non-enterprise accounts.

- **`instruqt track list`** doesn't work as expected with the current CLI version —
  use the Instruqt web UI to see available tracks.

- **`.remote` files** appear after `instruqt track pull` when local and remote differ.
  They are conflict markers — review, accept one version, delete the `.remote` files,
  then push with `--force`.

## Adding a New Challenge

1. Create `exercises/N_topic/practice/` and `solution/` with pom.xml and src/
2. Create `track/NN-topic/` directory
3. Copy scripts from an existing challenge, update paths and exercise number
4. Write `assignment.md` — no `id:` field, slug = directory minus `NN-` prefix
5. Copy `config.yml` from an existing challenge (they're all identical)
6. `git push` (triggers image rebuild for new exercise source)
7. `cd track && instruqt track push`
8. `instruqt track pull` to capture generated IDs
9. `git add track/ && git commit && git push`

## File Editing Approach

When editing files in this project:
- Use `filesystem:edit_file` with `oldText/newText` for surgical edits
- Use `filesystem:write_file` for full rewrites (when >3 sections change)
- Always read the file first before editing — don't rely on memory of previous edits
- The filesystem MCP cannot access dotfile directories (`.github/`) — those must be
  edited manually or via terminal
- After editing `track/` files, always run `instruqt track validate` before pushing
